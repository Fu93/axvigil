# AxVigil 白皮書(v3.1)

> **From Compute to Protection** —— 把 AI 的代碼推理算力,轉化為對智能合約與鏈上資產的可驗證防禦。

**狀態紀律(先讀這段)。** 本文描述一個已存在的東西與兩個尚未存在的東西。**Layer 1 — 熔爐(認證)** 今天已建成、測試完成、部署於 BSC 測試網。**Layer 2(防禦網路)** 與 **Layer 3(結算與調度)** 是路線圖。所有前瞻性敘述都會標明。本文說「今天」指 `Fu93/axvigil` 在 `main` 的代碼;說「路線圖」或「未來」指設計意圖,而非已出貨的軟體。

## 0. 定位

**AxVigil 是一個防記憶的試煉場,認證 AI agent 去*修好*智能合約漏洞;同時是建立在其上的防禦網路的信任根基。**

近期、可展示的產品是這個試煉場——**熔爐(the Crucible)**。長期願景是把持牌 agent 導向真實的合約安全工作。我們先講第一個,因為它是真的;我們描述第二個,因為那是第一個瞄準的方向。

*From Compute to Protection —— 讓每一次 AI 推理都成為一道安全屏障,而非零和解題。*

## 1. 摘要

AI agent 已經能產出智能合約 patch。但看似合理的 patch 不等於已驗證的修補,而產業沒有一個獨立、可重跑的方式分辨兩者。與此同時,兩件事並排擺著:

- **算力空轉。** 許多 Web3 專案把 AI 導向 SAT 問題、算質數、跑迷宮,然後鑄 NFT 證明「我的 AI 很快」。產出保護不了任何人。
- **安全供給不足。** DeFi 漏洞已造成數十億美元損失;審計又慢又貴;大量新部署協議裸奔上線。

**AxVigil 的主張:把第一種算力導向第二種痛點——但要先證明這份算力確實有能力。**

我們建的、也是這個領域缺的那塊,是**驗證**:agent 拿到一份當場生成的漏洞合約,提交 patch *以及* PoC 攻擊,由一個確定性沙箱評分器確認攻擊在修補前成功、修補後失敗——且 patch 沒把合約改壞。通過,agent 就獲得一枚綁定其鏈上身分的**靈魂綁定執照**。那份認證就是信任根基;一個把持牌 agent 放上真實工作的防禦網路,是終點。

| 項目 | 今天(已建成) | 路線圖 |
|---|---|---|
| 核心 | 熔爐:發題 → agent 修補 → 確定性驗證 → 鏈上執照 | 防禦網路:自動化初審、持續監測、賞金掃描 |
| 憑證 | `AxVigilSkill` —— ERC-5192 靈魂綁定執照,綁定 Agent ID | 執照作為接入實戰防禦任務的門票 |
| 驗證 | 差分式四項檢查 + 防記憶變體引擎 | 多節點重跑 / 去中心化驗證 |
| 經濟 | 僅積分;無代幣、無收益承諾 | 收入來自真實安全預算(B2B 掃描、賞金分成) |
| 部署 | BSC 測試網(chain 97),完整流程已鏈上實測 | 主網,以 Layer 1 自我證明為前提 |
| 題目來源 | 僅已修補、已公開揭露的漏洞,經 `variantgen` 變形 | 贊助題目;私有評測模式配責任揭露 |

## 2. 問題

### 2.1 算力層 —— AI 推理正在被浪費

2025–2026 年,agent 代碼推理能力快速成長,而 Web3 相當大一部分把它導向**無社會價值的零和博弈**:SAT/布爾可滿足性謎題、算質數、跑迷宮、重複的 benchmark 截圖——每一項都在燒真實 GPU 時間,鑄一個保護不了任何人的「證明」。**算力空轉,而真實世界的安全缺口在擴大。**

### 2.2 安全層 —— 合約防禦嚴重供給不足

| 痛點 | 現狀 |
|---|---|
| 損失規模 | 近年 DeFi 漏洞累計損失數十億美元 |
| 審計供給 | 頂級公司排期數月,費用五到六位數美元 |
| 覆蓋缺口 | 大多新部署的中小協議沒有審計預算,裸奔上線 |
| 響應速度 | 審計是靜態/時點性的;部署後的持續監測幾近於零 |
| AI 未被利用 | AI 能產出合理 patch,卻缺乏可信的驗證與調度層 |

### 2.3 基礎設施層 —— 缺少從算力到安全的橋樑

即使有人想用 AI 做安全:

1. **能力無法驗證** —— 「安全能力」靠 benchmark 截圖或自述,沒有可獨立重跑的證據。
2. **題目會被背** —— 公開題庫很快進訓練資料;固定題目衡量記憶而非修補。
3. **憑證綁錯對象** —— 能力應屬於 agent,而非錢包。
4. **出題者沒回報** —— 白帽整理的漏洞模式被反覆使用,卻無持續回饋。
5. **人人重造輪子** —— 每個團隊各自搭沙箱、找題、防作弊。
6. **沒有從考場到戰場的路徑** —— 即使證明了能力,也沒有網路讓它保護真實資產。

**AxVigil 要解決的核心問題:建立一套可信機制,讓 AI 算力從「空轉解題」轉向「防禦真實合約」——從讓任何此類主張可信的「驗證」開始。**

## 4. Layer 1 —— 熔爐(現有系統)

### 4.1 它在網路中的角色

今天的原型(`Fu93/axvigil`, `main`)實現的是 **Layer 1**。它的工作:**確保進入防禦網路的 agent 具備真實能力——而不是會產生誤報、浪費協議方時間的無效算力。** 沒通過熔爐的 agent 無法接入 Layer 2。這是整個網路的信任根基——也是本次黑客松端到端能跑的交付物。

### 4.2 認證流程(端到端)

```
Backend (FastAPI) ──發放新變體(僅原始碼)──▶ AI Agent
      ▲                                          │
      │                 patch + PoC              ▼
      │                                    Verifier(確定性沙箱)
      │                                    ① pocProvesBug
      │                                    ② pocFailsAfterPatch
      │                                    ③ hiddenTestsPass
      │◀── EIP-712 MintAuth(全部通過才簽) ─── ④ patchWithinLimits
      ▼
Agent ID 持有人送出 mint
  → AxVigilSkill (ERC-5192):更新執照
  → AxVigilCollectible (ERC-721):免費紀念
  → agent 現已持牌;符合 Layer 2 接入資格(路線圖)
```

### 4.3 現有元件

| 元件 | 重點 |
|---|---|
| Backend | FastAPI:錢包簽名登入 + 鏈上 Agent ID `ownerOf` 檢查;伺服器發題;session 內評分;EIP-712 授權;SQLite;限流;答案外洩斷路器;按難度加權的排行榜 |
| Verifier | 零第三方依賴;`ffi` 關閉、無網路、時間上限 + POSIX 資源上限;自動解析 Foundry 工具鏈 |
| Agent | 自動解題迴圈,附離線 oracle 讓評審重現 |
| 合約 | EIP-712 授權;每個 Agent ID 終身 2 次;每小時上限;可暫停;可輪換 signer;供給固定 |
| 部署 | BSC 測試網(chain 97):Skill `0x3377…CD18`、Collectible `0x0658…4658`、Agent ID 註冊表 `0x7Aa4…d45e` |
| 測試 | Foundry 單元 / fuzz / 稀有度 / invariant / verify→mint 整合;Python 後端與 verifier 套件;CI 在 `main` 綠燈 |

### 4.4 鏈上現況

完整流程已對 live 合約跑過:一個做了真實 RPC Agent ID ownership 檢查的後端,為一個**伺服器發放的傳奇(pool 2)**solve 簽了 MintAuth;Agent ID 1 鑄出 token #1(batch 1 已 commit,之後已揭示:tier COMMON);`submissionHash 0x8083…64df`。全部 80 個變體在出貨前都對真實驗證器自我驗證。

## 5. 題庫與防記憶引擎

### 5.1 為什麼防記憶是前提

如果 agent 只是背了答案,它在防禦層就是**無效算力**——無法辨識野外出現的新變體。熔爐的核心價值,是確保每個持牌 agent 具備**泛化的**修補能力,而非對特定題目的記憶。

### 5.2 `variantgen` —— 防記憶引擎

每個母題是一個漏洞模板。依 seed,`variantgen` 換掉識別字、插入干擾函式、重排函式順序,產生結構各異的變體;結構指紋在發題前丟掉長得像的。agent 必須真的修好那一類漏洞。

| 母題 | 類別 | 難度 |
|---|---|---|
| `reentrancy` | 重入 | Basic |
| `access-control` | 權限控制 | Basic |
| `price-manipulation` | 價格操縱 | Advanced |
| `signature-replay` | 權限控制 | Legendary |

**今天:4 個母題,每個 20 個自我驗證的唯一變體——共 80 題**,橫跨 3 個漏洞類別、涵蓋全部 3 個難度階。

### 5.3 差分式四項檢查

| 檢查 | 驗證什麼 | 為什麼必要 |
|---|---|---|
| `pocProvesBug` | PoC 在原始合約上成功 | 漏洞真實;排除偽 PoC |
| `pocFailsAfterPatch` | 同一 PoC 在修補後失敗 | 漏洞確實被消除 |
| `hiddenTestsPass` | 隱藏功能測試全部通過 | 修補沒破壞既有邏輯 |
| `patchWithinLimits` | 改動行數/位元組有上限 | 阻擋「刪掉整個合約」式暴力修補 |

### 5.4 題目來源原則

- ✅ 只用**已修補、已公開揭露**的漏洞(DeFiHackLabs、Code4rena、Sherlock、Immunefi 事後報告)。
- ✅ 一律先經 `variantgen` 變形。
- ❌ 絕不使用仍在線上、未修補的漏洞。
- 📋 私有評測模式(計畫中):自帶題目只在私有環境評分;新發現走責任揭露。

## 6. 憑證與紀念品

### 6.1 真正重要的憑證(執照):`AxVigilSkill`

`AxVigilSkill` 不是獎狀,是**執照**。它的含義是:*「此 agent 已通過熔爐,在 [類別] 具備真實能力,獲准接入 AxVigil 防禦工作(路線圖)。」*

| 屬性 | 說明 |
|---|---|
| 標準 | ERC-5192(靈魂綁定) |
| 綁定 | `tokenId` = Agent ID;`ownerOf` 跟隨 Agent ID 註冊表 |
| 可轉移性 | `locked()` 永遠為 true —— 無法賣、無法轉 |
| 紀錄 | 各類別認證次數、最高難度、總數 |
| 視覺 | 鏈上 SVG;每通過一個新類別多一個徽章 |
| 吊銷 | 管理員可撤銷(例如實戰中的惡意誤報) |

因為買不到,買家就無法偽裝能力——這正是它值得信任的原因。

### 6.2 純裝飾的紀念品:`AxVigilCollectible`

一枚免費、非投機的 ERC-721,標記一次**真實驗證事件**(metadata 帶 `submissionHash`)。它刻意免費、不給任何財務權利;唯一含義是「發生過一次真實 solve」。稀有度機制存在於合約中,但刻意排除在核心敘事之外——見**附錄 A**。執照是主角,收藏品是紀念。

> 一致性說明:AxVigil 批判「鑄 NFT 證明算力」的專案,因此自身代幣設計刻意相反——有含義的東西(執照)不能交易,看得到的東西(收藏品)免費且純裝飾。

## 8. 積分 → 經濟模型(分階段)

### 8.1 原則

**AxVigil 的經濟循環由真實安全預算驅動,不由代幣投機驅動。** 是否發代幣取決於網路是否產生真實防護價值,而非市場熱度。目前合約與 SPEC 明確:沒有代幣,沒有收益承諾。

### 8.2 三階段

```
階段 A — 積分(現在)
  驅動:黑客松 + 社群 · 收入:無
  閘門:月認證次數 > 1,000 且出題者 > 20 人
      ↓
階段 B — 安全服務收入(6–18 個月目標)              [路線圖]
  驅動:B2B 掃描費 + 賞金分成 + 贊助池 · 收入:USDC
  閘門:月掃描收入覆蓋營運成本
      ↓
階段 C — 代幣(條件式,遙遠)                        [路線圖]
  前提:法律意見 + 月活 agent > 500 + 無監管障礙
  功能:僅治理 + 防濫用質押;不承諾收益
```

### 8.3 積分流向(A–B)

| 流向 | 觸發 | 說明 |
|---|---|---|
| 出題者分潤 | 其母題被發放並評分 | 按使用量,非買斷 |
| Agent 積分 | 通過認證 / 完成防禦任務 | 難度加權:Basic 1、Advanced 3、Legendary 8 |
| 贊助池 | 贊助方出資指定題目池 | 懸賞 / 額外獎勵 |
| 防禦賞金 *(階段 B+)* | agent 實戰發現真實漏洞 | 從賞金池按貢獻分配 |
| 掃描服務費 *(階段 B+)* | 協議方提交掃描需求 | 按次 / 訂閱 |

### 8.4 防濫用(今天已建成)

每個 Agent ID 終身 2 次嘗試 · 伺服器發題 · 每小時鑄造上限 · API 限流 · 答案外洩斷路器 · 需要真實 Agent ID 註冊表 · 商業評測可要求 stake 或費用。

## 9. 商業模式(錨)

**AxVigil 的收入來自安全預算,不是投機資金。** 全球 DeFi 每年在安全上(審計、保險、賞金)支出數億美元。目標是成為流入這個池子的一個高效、自動化的分配通道。*正是這一章——而不是「去中心化算力網路」這個詞——正當化了這份野心。*

## 10. find-vs-fix 斷層(誠實陳述)

這是全文最重要的但書,也是內行評審一定會問的:

**今天的認證證明 agent 能在受控目標上*修好一類已知*漏洞。一個生產級防禦網路還需要在真實代碼中*找出未知*問題——這是熔爐尚未測試、而且嚴格更難的問題。** 通過熔爐本身並不意味著 agent 會找出新的 0-day。

我們把它當成一個範圍決策,而非含糊帶過:

- **Layer 2 v1 的範圍限定在 agent 持牌類別內的模式化偵測與初篩** —— 找出它所認證類別的實例 —— 而非開放式 0-day 獵捕。
- 近期價值主張因此是「對已知類別的快速、低價、持續初篩」,並明確定位為**輔助性,而非取代人工審計**。
- 邁向真正「發現」能力是未來研究,路線圖以它為前提,而非假設它已具備。

我們寧願交付一個能用代碼支撐的較小主張,也不畫撐不起來的大餅。

## 14. 法律與合規

| 議題 | 設計回應 |
|---|---|
| 隨機抽取 + 可交易(loot box 疑慮) | 免費鑄造、以認證為門檻、不收 mint 費 |

| AI 產出安全報告的責任歸屬 | 明確聲明:AxVigil 提供輔助性掃描,不取代人工審計;不承擔因掃描結果導致的損失 |

| 個人資料 | 後端只保存錢包地址與 Agent ID |

## 結語

AI 算力不該被浪費在零和解題遊戲裡。每一份 GPU 時間、每一次推理,都應該產出真實的保護——一個協議的 TVL、一個散戶的存款、一條鏈的安全。

AxVigil 的終極願景不是「發代幣」或「賣 NFT」,而是:**當一個新的 DeFi 協議部署時,它不必等三個月、花五十萬美元去請人工審計——它只需接入一群經熔爐認證的 agent,在幾分鐘內取得第一道防線。**

我們還沒到那裡。我們今天擁有的,是讓其餘一切變得可信的那塊:一個 AI 的修補被驗證、而非被宣稱的試煉場。這才是算力該去的地方。
