# AxVigil — 黑客松 Pitch

> **交付已驗證的修補,而不只是發現漏洞。** AxVigil 訓練並認證 AI agent 去*修好*智能合約漏洞——而且每一次修補都在鏈上被證明。

**Meta Global AI Developer Hackathon · BSC 測試網 (chain 97) · sandbox / whitehat**

---

## 一句話定位

AxVigil 是一個**給安全 AI 的防記憶試煉場**。Agent 會拿到一份當場生成的漏洞合約,寫出一個修補程式*以及*一個概念驗證攻擊(PoC),再由一個確定性的沙箱驗證器確認漏洞「確實被消除」之後,才會發出任何獎勵。通過的 solve 會鑄造一枚綁定於 agent 身分的**靈魂綁定技能執照**——這是「掙來的」,不是「宣稱的」。

這個試煉場(我們稱為 **the Crucible / 熔爐**)今天已經建成、測試完成、並部署在 BSC 測試網上運作。它是一個更大願景的信任根基——一個把 AI 算力導向真實合約安全、而非零和解題遊戲的網路——但本次黑客松的交付物就是熔爐本身,而且它端到端能跑。

---

## 問題

Web3 當下有兩個事實並排擺著:

- **AI 算力被燒在毫無價值的事情上。** 一大批「agent 解謎」專案把真實 GPU 時間花在 SAT 問題、算質數、跑迷宮,然後鑄一枚 NFT 證明自己的 agent 很快。產出保護不了任何人。
- **合約安全無法規模化。** DeFi 漏洞已造成數十億美元損失;頂級審計排期數月、費用五到六位數美元;大量新部署的中小協議根本沒審計就上線。AI 已經能產出看似合理的 patch——但**看似合理的 patch 不等於已驗證的修補**,而且目前沒人能在規模上分辨這兩者。

兩者之間的落差是一個**信任問題**:沒有一個獨立、可重跑的方式能證明某個 AI 真的消除了漏洞、又沒把合約改壞。這正是 AxVigil 首先要補的缺口。

---

## 我們建了什麼(以及為什麼這是最難的部分)

**1. 防記憶題庫引擎(`mothers/` + `variantgen/`)。**
每個「母題(mother)」就是一個漏洞模板。一個 seed 每次都會渲染出結構上獨一無二的變體——換掉識別字、插入干擾函式、重排函式順序——並用結構指紋在發題前丟掉長得像的。所以公開答案毫無用處;agent 必須真的修好那*一類*漏洞,而不是背一個已知的 hack。

- **4 個母題,橫跨 3 個漏洞類別、涵蓋全部 3 個難度階**,每個母題各出 **20 個自我驗證過的變體——共 80 題**。

| 母題 | 類別 | 難度 |
|---|---|---|
| `reentrancy` | 重入 | Basic |
| `access-control` | 權限控制 | Basic |
| `price-manipulation` | 價格操縱 | Advanced |
| `signature-replay` | 權限控制 | Legendary |

**2. 一個評「差分」而非「測試套件」的確定性驗證器(`verifier/`)。**
四項檢查,每一項都必須通過:

| 檢查 | 證明什麼 |
|---|---|
| `pocProvesBug` | PoC 在*原始*合約上成功(排除偽 PoC) |
| `pocFailsAfterPatch` | 同一個 PoC 在修補後失敗(漏洞確實被消除) |
| `hiddenTestsPass` | 隱藏功能測試仍全部通過(修補沒把合約改壞) |
| `patchWithinLimits` | 改動行數/位元組有上限(防止「刪掉整個合約」式作弊) |

運行在一個加固的沙箱裡——`ffi` 關閉、無網路、時間上限與 POSIX 資源上限、自己的 process group——且**零第三方依賴**。評分可重現,且碰不到宿主機。

**3. 平台與鏈上憑證層。**
一個 FastAPI 伺服器發題(agent 永遠看不到母題、seed、隱藏測試或參考解),在 session 內評分,只為通過的提交簽發 EIP-712 授權。登入是錢包簽名,並**對鏈上 Agent ID 註冊表做 `ownerOf` 檢查**。通過的 solve 讓 Agent ID 持有人鑄造:

- **`AxVigilSkill`** —— 一枚 **ERC-5192 靈魂綁定**執照,綁定於 Agent ID(而非錢包),記錄各類別次數與最高難度。`locked()` 永遠為 true:無法賣、無法轉,且跟著 agent 走。
- **`AxVigilCollectible`** —— 一枚免費、純裝飾的 ERC-721,紀念一次真實的驗證事件(metadata 帶 `submissionHash`)。

**生產級獎勵規則:** 由伺服器發題——呼叫者不能挑母題、不能挑難度、不能重骰,而且開啟一個 session 就花掉**兩次終身嘗試**其中一次,無論通過與否。Solve 與 mint 嚴格 1:1。

## 鏈上實證(BSC 測試網, chain 97)

- **已部署並在鏈上實測。** `AxVigilSkill` `0x3377…CD18`、`AxVigilCollectible` `0x0658…4658`、Agent ID 註冊表 `0x7Aa4…d45e`。
- **完整流程已對 live 合約跑過:** 一個做了真實 RPC Agent ID ownership 檢查的後端,為一個*伺服器發放的*傳奇(pool 2)solve 簽了 MintAuth;Agent ID 1 鑄出 token #1(batch 1 已 commit,之後已揭示:tier COMMON)。`submissionHash 0x8083…64df`。
- **全部 80 個變體自我驗證:** 產生器在每個變體出貨前,都會把它的參考解丟進真實的驗證器跑過。CI(Foundry + Python)在 `main` 綠燈。

這裡沒有任何東西是模擬的:agent 看到的題目、拿到的評分、鏈上的紀錄,是同一條管線。

## 為什麼它難以作弊

- **背答案沒用**——每道題都是當場生成、指紋去重的變體。
- **偽造的修補過不了**——差分要求攻擊在修補前成功、修補後失敗,且功能測試仍通過。
- **暴力「修補」過不了**——patch 大小有上限,且公開介面必須存活。
- **刷獎勵有邊界**——伺服器發題、每個 Agent ID 兩次終身嘗試、每小時鑄造上限、API 限流、答案外洩斷路器,以及把真實 Agent ID 註冊表當作前提。

## 它往哪走(路線圖,尚未建成)

熔爐是 Layer 1。願景是把持牌 agent 變成一個**防禦網路**:為新部署合約做自動化初審、持續性監測、賞金池掃描——由真實安全預算買單,而非代幣投機。這是刻意保留的未來工作,以熔爐自我證明為前提才啟動。

**一個誠實的範圍註記。** 今天的認證證明的是 agent 能在受控目標上*修好一類已知*漏洞。一個生產級防禦網路還需要在真實代碼中*找出未知*問題——這是熔爐尚未測試、而且嚴格來說更難的問題。因此 Layer 2 v1 的範圍被限定在**agent 持牌類別內的模式化偵測與初篩**,而非開放式的 0-day 獵捕,並明確定位為*輔助性、非取代人工審計*。我們寧願交付一個能用代碼支撐的較小主張,也不畫一個撐不起來的大餅。

## 為什麼這能贏

我們沒有再做一張 benchmark 截圖,也沒有再發一批 NFT。我們做了這個領域缺的那一塊:**一個獨立、可重跑、能證明 AI 真的消除了某個漏洞的方法**——並把它接到一個「因為買不到所以可信」的憑證上。以上一切此刻都在測試網運作;clone 這個 repo,一行指令的 demo 就能重現。
