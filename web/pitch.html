[:THE PROBLEM] _002 / 005

AI compute is wasted; contract security is under-supplied

Two facts sit side by side in Web3 — and the gap between them is a trust problem nobody has solved.

01 · Compute Burned on Nothing

Zero-sum puzzle solving

A wave of "agents solving puzzles" projects spend real GPU time on SAT instances, prime hunts, and toy puzzles, then mint an NFT to prove their agent is fast. The output protects no one.

02 · Security Cannot Scale

Plausible patches aren't verified fixes

DeFi exploits have cost billions; top audits take months and tens of thousands of dollars; most new protocols deploy unaudited. AI can draft patches — but nobody can independently tell a plausible patch from a verified fix at scale.

[:THE CRUCIBLE] _003 / 005

The missing piece: proof that a fix actually holds

Built, tested, and live on BSC testnet today. This is the hackathon deliverable — the trust root for everything that comes after.

01 · Anti-Memorization Engine

A fresh rewrite every time

Each vulnerability family is a bug template. A seed renames identifiers, injects distractor functions, and reorders bodies; a structural AST fingerprint discards look-alikes. 9 vulnerability families across 3 tiers (180 fresh rewrites total). The agent must understand the bug class, not recall an answer.

02 · Differential Sandbox Grader

Scores the difference, not tests

1. compile
Both original and patch compile cleanly under solc
2. pocProvesBug
PoC exploits the original vulnerable target
3. pocFailsAfterPatch
The exact same PoC fails after patch is applied
4. invariantsHold
Foundry state invariants and unit tests pass
5. surfaceAudit
Patch size is bounded; public interfaces intact
03 · On-Chain Capability Record

Earned, never bought

AxVigilSkill is ERC-5192 soulbound, permanently bound to the Agent ID (not a wallet) with on-chain ownerOf verification at session start. Server-dealt challenges, two lifetime attempts, strictly 1:1 solve-to-mint. Because it cannot be transferred, competence cannot be faked.

[:INTEGRITY & DEFENSE] _005 / 005

Why it cannot be gamed: 4 hard invariants

Invariant 1

Memorization is futile

Every challenge is a fresh, structurally unique rewrite with renamed identifiers and distractor functions. An agent cannot replay static diffs.

Invariant 2

Fake fixes fail verifier

The differential check demands proof that the exploit succeeds on the original and fails on the patch, while private unit tests remain 100% green.

Invariant 3

Brute-force cheat prevention

Patch line and byte counts are strictly capped; public ABI interfaces cannot be deleted or mutated to evade exploit execution.

Invariant 4

Farming bounded by policy

Challenges are dealt server-side with lifetime attempt caps, hourly quotas, and circuit breakers. Solves and on-chain mints remain strictly 1:1.

Where It Goes · Stated Honestly

The Crucible is Layer 1 — the trust root for an autonomous defense network (continuous scanning, automated bug bounty triage) funded by actual security budgets, not token speculation. One honest caveat: a passing record proves an agent can fix a known vulnerability class; finding unknown zero-days is a distinct, harder frontier. Layer 2 v1 is therefore scoped to assistive pattern-class triage within an agent's certified classes, rather than a replacement for human security audits.
